# Audita Acessibilidade 1.1.51 — correção da rejeição "Red Titanium" (código ofuscado)

Reenvio da 1.1.50 com uma única correção de empacotamento. A funcionalidade é a mesma descrita nas
[notas da 1.1.50](1.1.50.md).

- ZIP: `release/audita-acessibilidade-1.1.51.zip`, com **207 arquivos**.
- SHA-256: `d44ceae5b6a86d71301870ad227bf1dee67166c472028c5b0996a92d1bf3a21d`.
- Item da loja: `pehaoepmcnngopfknnmlbfdhcimfdccb`.

## A rejeição

A Chrome Web Store rejeitou a 1.1.50 pelos Requisitos de Legibilidade de Código (ID de referência
**Red Titanium**, roteamento FZSL), apontando em `vendor/axe/axe.js`:

```js
return LT + SCRIPT + GT + content + LT + '/' + SCRIPT + GT;
```

O trecho não é nosso: é o módulo `object-create` do core-js, embutido no build oficial do axe-core 4.13.0.
Ele monta uma tag `<script>` e uma URL `javascript:` por concatenação de strings e as escreve num documento
ActiveX ou num iframe oculto, como polyfill de `Object.create` para Internet Explorer 8 e anteriores. A
revisão da loja trata esse padrão como ocultação de código.

## Correção

- `scripts/vendor-axe.mjs` gera `vendor/axe/axe.js` a partir de `node_modules/axe-core/axe.js`, após conferir
  o SHA-256 oficial (`138a93a4…6d88`). A única alteração troca o módulo `object-create` por
  `module.exports = Object.create;` e acrescenta um aviso de modificação após o cabeçalho MPL-2.0, que fica
  intacto. O resto do axe é byte a byte o pacote oficial.
- Sem mudança de comportamento: a extensão exige Chrome 116+ (`minimum_chrome_version`), onde
  `Object.create` é nativo; o original já usava `Object.create || polyfill` e o polyfill nunca executava.
- Novo SHA-256 do runtime: `12af8a1c94f7b47e5ad0cbec570cd7a3428d6ca31fa2a87277bd99e5c5654060`, fixado em
  `AXE_PROVENANCE.runtimeSha256`, `scripts/verify-project.mjs` e `test/release-assets.test.js`.
- Guardas contra regressão: `test/vendor-axe-readability.test.js` e `npm run verify` exigem que o axe seja
  reproduzível pelo script e que nenhum arquivo de `src/` ou `vendor/` contenha os padrões apontados
  (`LT + SCRIPT + GT`, `'java' +`, `ActiveXObject`).
- `scripts/build-release.mjs` fixa a permissão dos arquivos do ZIP em 0644, a mesma dos pacotes anteriores.
  Sem isso o digest dependia da máquina de build. Com a mudança, o ZIP da 1.1.50 foi reconstruído byte a byte
  (`eee5500f…3c66`) numa máquina Linux.

## Evidências

- `node scripts/vendor-axe.mjs --check`: reproduzível, SHA-256 `12af8a1c…4060`.
- ZIP 1.1.51: 207 arquivos, `manifest.json` 1.1.51 na raiz, zero ocorrências dos três padrões e nenhum `.min.js`.
- Fase lógica de `npm test` (Linux, Node 22): **4.288 testes; 4.277 aprovados, 9 falhas, 2 skips**. As 9 falhas
  (alinhamento por direção de idioma, marcadores de página e abertura do relatório de Tab) se repetem
  idênticas no commit 1b5f7b1 (1.1.50) no mesmo ambiente, que não tem `Intl.Locale#getTextInfo`. Não têm
  relação com esta correção.
